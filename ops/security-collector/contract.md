# Collector implementation contract (#2138)

This is an implementation/review contract, not a deployed runbook. Maintained operation belongs on the [Kubescape Wiki](https://github.com/RovxBot/homelab-infra/wiki/Kubescape). `wiki-proposal.patch` is a security-sensitive proposal against that separate repository, retained for review rather than published as accepted architecture. Its pinned Wiki base is in `wiki-base.txt`; check/apply it in that checkout with `git apply --unidiff-zero --check` / `git apply --unidiff-zero`.

## Stage B source boundary (offline qualified, production disabled)

`Pipeline` in `pipeline.py` defaults disabled, returns safe previews only, and has no issue client. Explicit construction/enabling is required to make reads. No deployment, scheduler, Service, credential, RBAC binding or active assessment change ships. `stage-b-evidence.json` retains pinned source review, local qualification and unqualified production gates. `stage-b-requirements.json` is the resource/security contract for a separately approved rollout, not an installable manifest.

`sources.KubernetesAPI` uses only GET against one configured HTTPS API origin, verifies CA/hostname, disables redirects/proxies, rereads projected tokens on every call, limits responses to 4 MiB and times out after ten seconds. The authenticated API server and kubelet log path establish transport identity; log fields cannot authenticate themselves. The token's identity/namespace RBAC and CA/origin are trusted provisioning inputs. There is no unauthenticated receiver or sender-supplied inventory/context. Application authentication remains required with Cilium enforcement disabled.

`RuntimeLogReader.poll(now)` verifies the reviewed node-agent DaemonSet UID, allowlisted named Pod UID and owner UID, namespace, ServiceAccount, metal6 node, pinned image/index or previously qualified amd64 child, container ID and restart count before and after the log read. It independently resolves enrolled Deployment → ReplicaSet → Pod UID ownership and verifies running image/container/node before accepting an event. All replicas must be ready with one running digest. Other workload/container types are unqualified. Enrolment and source Pod/DaemonSet UID identity are private reviewed configuration; none is enabled by this PR.

Log polling requests kubelet timestamps with a one-second overlap and a 4 MiB snapshot ceiling. It rejects partial/oversized/malformed snapshots, duplicate JSON keys, nonfinite constants, unsupported FIM events and mismatched attribution. Ordinary non-event logger records are skipped. A hashed last-line anchor plus source container identity survives restart. Initial boundary, missing overlap, agent replacement/restart, disconnection over five minutes, read failure and backpressure are explicit gaps. Gaps latch in the cursor; subsequent polls/replays cannot certify missing history. No automatic gap-reset API ships. A quiet successful read is a **reader heartbeat**, not proof of agent detector liveness or complete emission. Kubelet rotation can lose records before polling, and truncation/rotation that preserves the overlap anchor cannot be proven absent. The transport promises bounded durable acceptance and detectable observable gaps, not lossless upstream capture. No node-agent/exporter configuration change is needed or included.

`Intake` stores normalized observations only in the same private SQLite database as collector receipts. Queue and cursor commit together. Draining into collector receipts is at least once and idempotent across either crash boundary. It never drops pending evidence or live replay identities to make space. Limits: 1,000 pending events / 8 MiB, 64 MiB database pages, a separate filesystem budget for the rollback journal, and the original collector receipt/incident/rate limits below. Failed draining retains the queue. Pending evidence older than seven days is fenced for operator review, not discarded. A clean/positive vulnerability event left by a crash requires current reader requalification before draining; a persisted `qualified` flag cannot authorize resolution after a later failed assessment. Saturation may prevent persisting a heartbeat; the caller must surface its static failure and the external supervisor must treat absent checks as stale.

Persisted reader status exists even without incidents. Each source/workload/category has current state/reason, check time, last successful qualification, last gap and bounded gap counter. Polls, including failures, have a persisted minimum 15-second interval. `Intake.health(now)` must run each scheduler tick, including quiet periods; after five minutes without a check it reports stale, invalidates only that category and refreshes evidence expiry. Deploying a supervisor and wiring a private health signal into existing monitoring remain separate approval/qualification gates. A stopped process cannot report its own failure.

`AssessmentReader.poll(workload, now)` never starts a scan, clears `inflight.json`, takes the runner lock or writes its history. It reads bounded regular files without following symlinks; gzip expansion is bounded. It joins `records.json`, `latest-vulnerability.json`, `coverage.json`, a unique retained run result, request, successful terminal status, cache checksum/SQLite audit, report/SBOM and workload summary. The DB trust root is the repository-reviewed verified lock; archive source checksum, schema/build, publisher document and SQLite identity must agree with retained execution evidence. It verifies report findings/fix counts, SBOM identity hashes and attribution through the existing strict adapter. Fresh named API rereads of all three stored objects and a second independent inventory/history snapshot must agree. Missing history, fences, failed/unknown/stale latest attempts, incomplete/excluded/unsupported coverage, changed objects or workload identity are never clean success. An overall unhealthy latest vulnerability batch conservatively gates all workloads, including peers with cached successes.

The runner records UID/digest but **no historical generation**. Stage B records the first independent observation time of each UID/generation/digest epoch. A qualified scan must start after that observation. Kubernetes generation is monotonic within a UID; an unchanged later generation and matching UID/digest bind the scan to the observed epoch. A current coverage generation cannot retroactively qualify an older scan. Existing history may therefore remain unknown until an ordinary scheduled scan follows the first inventory observation. No new scan or CronJob change is authorised. UID recreation invalidates recovery even if generation/digest repeat. Report freshness is 72 hours, DB seven days, latest batch/coverage 26 hours, independent inventory one hour, reader heartbeat five minutes; all gates apply together. Freshness does not prove whole-cluster coverage.

The isolated tests construct runner history with the **active runner's own** `check_report`, `row_key` and `coverage` functions, use synthetic real-format pinned exporter/Grype envelopes, and mock all cluster sources/external writes. A separate local HTTPS server exercises actual CA checks, token rotation, redirects and response limits. They are not retained production evidence, live canaries, an image build, or an unattended rollout. Stage A tests remain in the same focused suite.

### Stage B rollback/recovery contract

For this undeployed library, leave `Pipeline.enabled=False` (default), retain private SQLite and revert the Stage B code PR; no production action is required. For a later separately approved installation: disable its scheduler/readers through a reviewed Flux PR, retain the same writer-disabled policy and revoke only its read credential if needed. Preserve SQLite, pending queue, cursor anchors, receipts, gap/health state, inventory epochs, unresolved issue-write fences and existing incidents. Record the stop as missing telemetry; do not reset cursors, discard pending records or delete scanner reports/history/SBOMs/PVCs. Stop the single writer before copying the mode-0600 database and any recovery journal. Restore with no writes enabled, run integrity/size checks, drain only runtime replay and requalify every pending assessment against current sources. Reconnects retain historical gaps; new generation observations need ordinary post-observation scans. Resource expansion/archival or gap acknowledgement needs a reviewed action; no destructive automatic recovery ships. Stage A rollback tests and Stage B queue/restart/disabled-coordinator tests establish local behavior only; live rollback remains unqualified.

## Entry points

- `scripts/security_collector/adapters.py`: `EventAdapter.read(bytes, Deployment, now)` returns one immutable `Observation`. `RuntimeStderrAdapter` consumes one JSON line from the pinned exporter. `VulnerabilityAdapter(AssessmentContext)` consumes a private `{report, sbom, summary}` bundle. Neither adapter fetches data or authenticates a sender. These are private caller interfaces, not network endpoints.
- `model.py`: validated source/category, rule/advisory IDs, workload/container, optional image digest, severity, observation ID/time, provenance, confidence, freshness, remediation and qualified-clean assessment. Stage B also binds workload UID. `Deployment` and `AssessmentContext` come from independent trusted readers; accepting them from an event sender would defeat the recovery checks.
- `engine.py`: `Collector.deployment`, `ingest`, `telemetry`, `refresh`, and trusted-operator `disposition`. Transactions commit sanitized state and replay receipts together. Raw input is transient and never saved. First/last observation, occurrence/assessment count and a bounded evidence-change history belong to each incident. `telemetry(workload, state, *, source, category)` must be called on reader/qualification failures with an explicit validated source/category; it invalidates only matching incidents. Runtime and vulnerability telemetry for the same workload cannot invalidate each other; source silence never implies remediation.
- `issues.py`: explicit internal-workload-to-`Publication` mapping is required. The mapping, public aliases, remediation issue and related issue numbers are reviewed configuration. No mappings ship enabled. `Delivery` defaults to `enabled=False` and `allow_closure=False`. There is **no production GitHub client, deployment, receiver, credential configuration or network-enabled CLI**. Tests alone inject a mock and enable delivery.

## Identity and recovery

Runtime identity is SHA-256(source, category, logical cluster/namespace/kind/workload/container, rule). Vulnerability identity substitutes `image-backlog` for the rule: CVEs and image digests update the same backlog. Controller resolution uses supplied independent inventory, never guessed pod-name suffixes. Logical workload recreation retains the incident; deployed generation/digest and evidence snapshots show changes.

Runtime replay identity hashes workload/rule plus upstream uniqueID, falling back to the full nanosecond timestamp/container ID/PID. It never persists the raw identifier or process data. Without a uniqueID, exactly identical fallback tuples collapse; this is not a claim of a lossless transport. Vulnerability replay identity hashes workload/digest/report timestamp/locked DB checksum. Report mutation without a new assessment timestamp is not new assessment evidence.

Runtime incidents require operator investigation. `acknowledged` keeps the incident unresolved. Trusted `false_positive`, `investigated`, or `accepted_risk` disposition requires a reviewed repository issue number; a new observation reopens the incident, while exact replay preserves disposition. Event fields cannot invoke disposition. New digest/generation invalidates vulnerability recovery. A clean assessment resolves only with ready report/SBOM, valid manifest/config identity hashes, summary workload/container/ref attribution, matching locked DB, post-deployment report, current generation, fresh independent inventory, healthy latest attempt and complete coverage. Report age is at most 72 hours and DB age at most seven days; inventory expires after one hour. Expired/missing inventory or failed/stale telemetry reopens assessment-based resolution. Following a gap, fresh qualification is required; replay alone does not restore resolution. Unsupported/malformed reports must be surfaced as unsupported/unknown, never empty success.

Vulnerability finding fields (`identities`, `finding_count`, `severity`, `remediation`, `provenance`) retain the last qualified snapshot independently of the latest attempt's `assessed_at`, confidence, freshness and recovery state. `findings_at`, `findings_digest`, `findings_generation` and `findings_qualified` identify that snapshot, including after restart, history rollover or a deployment change. Before any qualified snapshot exists, finding fields may contain unqualified evidence, labelled accordingly. A newer assessment replaces a qualified snapshot only if it passes current digest/generation, inventory, confidence, freshness and validity gates; a qualified clean result may replace it with zero findings. Unqualified empty or changed reports, telemetry gaps, expiry and deployment changes cannot erase the retained identifiers, severity, count or scanner fix hint. Public output labels the last qualified assessment and its time/digest/generation separately from the latest assessment attempt and current deployed digest.

Admission/policy findings and service-health recovery cannot resolve these incidents. Gatus, Kyverno issue sync, Renovate/CI and Flux retain their existing ownership and code.

## Bounds and delivery

| State/action | Default bound |
| --- | --- |
| Runtime JSON / assessment bundle | 1 MiB / 4 MiB |
| CVE/GHSA IDs per complete assessment | 5,000; reject rather than truncate qualification |
| Incident records, including resolved keys / inventory entries | 200 / 200; saturation rejects new entries |
| Replay receipts / acceptance window | 20,000 / seven days; reject saturation, never evict live receipts |
| Accepted observations | 1,000 per rolling hour, persisted across restart |
| Evidence snapshots / public IDs | Latest 32 per incident / first 50 plus full count |
| GitHub requests / writes / creates | 60 per hour / 10 per hour and 20 per day / three per day |
| Delivery backoff | 60 seconds initially, exponential to one hour; persisted |

Normalized state uses a private mode-0600 SQLite file and one writer. Resolved keys are bounded tombstones, not automatically deleted: archival/retirement at capacity requires a future reviewed policy. Receipt and quota retention is enforced on ingestion/reconciliation; SQLite reuses freed pages. Stage B adds the bounded normalized queue described above; there is no raw-retention subsystem.

Only confirmed High/Critical evidence initially qualifies for publication; existing tracked incidents receive updates, including reassessment/unknown state. Broader exploitability/baseline selection is pending review, not inferred from a zero-match report. Unknown advisory families outside CVE/GHSA reject the whole assessment. Public summaries include only typed identifiers/digests, reviewed workload aliases, canonical times/counts, fixed investigation text and configured same-repository issue numbers. They exclude raw names/descriptions, package versions/paths, command lines, environment, payload URLs and source-provided remediation text. Scanner fix availability is labelled unreviewed applicability; reviewed remediation is a separately configured issue link. No private Gitea source or evidence links are accepted.

The GitHub interface requires complete lookup across open/closed **collector-owned** issues and optimistic concurrency for updates. Human text before/after the owned marker is preserved. Missing/ambiguous markers fail closed. Persisted create intent fences a crash/lost response. After an uncertain create, lookup may recover an existing issue, but an empty lookup never authorizes another create. No automatic fence-clearing API exists. Retries are for lookups/idempotent updates only. Exceptions are never copied into persisted state or public output. Stage B must implement and qualify these guarantees against GitHub before any writes are enabled.

## Local validation

```sh
python3 -m unittest discover -s scripts/tests -p 'test_security_collector*.py' -v
python3 -m compileall -q scripts/security_collector scripts/tests/test_security_collector*.py
```

The suite exercises adapters → durable state → renderer → mocked GitHub, including restart/outage/ambiguous-write and disabled rollback paths. Fixtures are synthetic: R1000 shape and severity follow the [accepted canary](https://github.com/RovxBot/homelab-infra/issues/2136#issuecomment-7087742825) and pinned exporter/types; assessment envelope follows the existing qualified runner and live field-name checks, with positive matches from the [Grype contract](https://github.com/anchore/grype/blob/v0.121.0/grype/presenter/models/match.go). They are not retained production logs or fresh scanner acceptance. Source/pin observations and exact missing integrations are in `compatibility.json`. Existing Repo Checks automatically discovers `test_security_collector.py` for scripts changes; no scanning schedule or production CI credential is added.
